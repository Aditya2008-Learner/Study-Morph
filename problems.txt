[PROBLEM 001]
Severity: Medium
Category: Backend / Unhandled Exception
Page/Feature: API: Quiz Submission (`POST /api/quiz/{quiz_id}/submit`)
Title: `POST /api/quiz/{quiz_id}/submit` crashes with 500 Internal Server Error when answers payload is formatted as a dictionary/map

Steps to reproduce:
1. Generate a quiz via `POST /api/quiz/generate` with payload `{"subject": "CS201", "topic": "Asymptotic Analysis", "num_questions": 3}`.
2. Submit answers formatted as a dictionary `{"answers": {"q1": 0}, "time_taken_seconds": 30}` to `POST /api/quiz/{quiz_id}/submit`.
3. Observe the HTTP response.

Expected behavior:
The API should accept either a list of answer objects or normalize a dictionary of `{question_id: selected_index}`, or return a clean HTTP 422/400 validation error without raising an unhandled server exception.

Actual behavior:
The server throws an unhandled `AttributeError: 'str' object has no attribute 'get'` and returns `HTTP 500 Internal Server Error`.

Evidence:
* Console error: None (Server-side exception)
* Network request: `POST http://127.0.0.1:8000/api/quiz/e57a6c20-a081-4e42-91c5-4d3af5b7f13e/submit`
* HTTP status: 500 Internal Server Error
* Relevant source file: `src/backend/quiz_engine.py:120` and `src/backend/app.py:420`

Likely root cause:
In `src/backend/quiz_engine.py` (line 120), `QuizEngine.grade_attempt()` iterates over `submitted_answers` assuming each item is a dict with `.get("question_id")`. When a JSON object/dict is passed, Python iterates over the dictionary keys (strings), causing `a.get(...)` to raise `AttributeError`.

Recommended fix:
In `src/backend/quiz_engine.py` (or `app.py`), normalize `submitted_answers` before iterating:
```python
if isinstance(submitted_answers, dict):
    submitted_answers = [{"question_id": k, "selected_index": v} for k, v in submitted_answers.items()]
```

[PROBLEM 002]
Severity: Low
Category: Navigation / Dead Link
Page/Feature: Homepage Navbar (`index.html`)
Title: Navbar links 'Workflow' and 'Roadmap' target nonexistent anchor IDs (`#workflow`, `#roadmap`)

Steps to reproduce:

2. Inspect the top navigation bar links: 'Features', 'Workflow', 'Roadmap'.

[PROBLEM 003]
Severity: Low
Category: Backend / API Parameter Validation
Page/Feature: API: PYQ Search (`GET /api/pyq/search`)
Title: `GET /api/pyq/search` requires mandatory `subject` query parameter resulting in HTTP 422 on general search

Steps to reproduce:
1. Send a GET request to `http://127.0.0.1:8000/api/pyq/search` without query parameters.
2. Observe the HTTP response code and error details.

Expected behavior:
A search endpoint should treat search filters as optional and return all available PYQ papers or an empty list when no filter is supplied.

Actual behavior:
The API rejects the request with `HTTP 422 Unprocessable Entity` stating `Field required: subject`.

Evidence:
* Network request: `GET /api/pyq/search`
* HTTP status: 422 Unprocessable Entity
* Response payload: `{"detail":[{"type":"missing","loc":["query","subject"],"msg":"Field required","input":null}]}`
* Relevant source file: `src/backend/app.py:194`

Likely root cause:
In `src/backend/app.py` line 194:
`async def search_pyq(subject: str = Query(..., description="Subject name or code"), college: Optional[str] = Query(None))`
The `Query(...)` ellipsis denotes a required parameter instead of an optional one.

Recommended fix:
Change `subject: str = Query(...)` to `subject: Optional[str] = Query(None)` in `src/backend/app.py`.

[PROBLEM 005]
Severity: Low
Category: Frontend / JavaScript Robustness
Page/Feature: Homepage Preset Handler (`index.html`)
Title: `loadSampleData()` relies on global/implicit `event` object which can cause undefined errors when invoked programmatically

Steps to reproduce:
1. In `index.html`, inspect the function `loadSampleData(key)` at line 1285.
2. Observe line 1290: `if (event && event.target && event.target.classList)`.
3. Call `loadSampleData('thermo')` programmatically from an external script or event listener without `window.event`.

Expected behavior:
The function should either receive the triggering element/event explicitly or guard against `window.event` safely.

Actual behavior:
In non-standard browser modes or when called from strict-mode code, accessing `event` directly without passing it as an argument or using `window.event` can raise `ReferenceError: event is not defined`.

Evidence:
* Source code: `src/static/templates/index.html:1290`
* Relevant source file: `src/static/templates/index.html`

Likely root cause:
Using the legacy implicit global `event` identifier in the function body rather than accepting `(key, event)` or querying active preset elements directly.

Recommended fix:
Update `loadSampleData` to query and set active chip explicitly:
```javascript
function loadSampleData(key, el) {
    const data = PRESETS[key];
    if (!data) return;
    document.querySelectorAll('.preset-chip').forEach(c => c.classList.remove('active'));
    if (el) el.classList.add('active');
    // ...
}
```
